# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-10-22 | Port the official PostHog hobby stack into kind; running compose beside kind is the fallback | The human asked for PostHog in kind |
| 2026-10-22 | The harness pins PostHog to commit `11eeef67` (the `latest` image when it was built) and fetches its config files at that commit | Config and app image cannot drift apart |
| 2026-10-22 | ClickHouse `idl` and `user_scripts` are copied from the pinned PostHog image by an init container | The UDF binaries are too large for ConfigMaps |
| 2026-10-22 | `autoresearch-row-policies.sql` is skipped from the ClickHouse init dir | It targets a user that exists only in `users-dev.xml` |
| 2026-10-22 | One Deployment plus Service per compose service, named like the compose services | PostHog's config files resolve hosts unchanged |
| 2026-10-22 | The ClickHouse pod sets `hostname: clickhouse` | Otherwise `clickhouse` resolves to the Service IP, ClickHouse does not recognise itself in the `ON CLUSTER` host list, and every distributed DDL in the migrations hangs |
| 2026-10-22 | Worker and temporal-django-worker crash loop until migrations finish, with no extra wait | The async migration check reads a missing table; compose behaves the same, and Kubernetes restarts them |
| 2026-10-22 | `enableServiceLinks: false` on every harness pod | Kubernetes service env vars like `TEMPORAL_PORT=tcp://...` otherwise override PostHog and Temporal settings |
| 2026-10-22 | Harness storage is `emptyDir` | The harness is disposable; data only needs to survive container restarts, not pod deletion |
| 2026-10-22 | The harness omits plugins, ingestion, capture, feature-flags, livestream, browserless, cymbal, valkey, the session recording seaweedfs, Elasticsearch and Caddy | The REST API used by the provider does not need them |
| 2026-10-22 | Redpanda runs with `--smp=1 --memory=1G` and binds RPC on `0.0.0.0` with no seed list | A pod cannot bind its Service hostname |
| 2026-10-22 | Topic creation is a Job that waits for the broker, then creates every topic from `topics.txt` in one `rpk` call | One call after the broker is ready |
| 2026-10-22 | The harness manifest holds a fixed, non-secret `SECRET_KEY` and `ENCRYPTION_SALT_KEYS` | The instance is local and throwaway |
| 2026-10-22 | `bootstrap.py` is idempotent: it reuses the admin, organization, project, member and license, and replaces the API key on every run | `up.sh` reruns against an existing cluster |
| 2026-10-22 | Bootstrap an enterprise License row for local dev/test | `ee/LICENSE` permits dev/test use |
| 2026-10-22 | Adopt the e2e expectation matrix from research; `warehouse_table` is unknown pending the harness | Self-hosted behavior per resource was researched; `warehouse_table` cannot be confirmed until the harness runs |
| 2026-10-22 | e2e credentials (API key, organization ID, project ID, second user UUID) come from the harness bootstrap locally and in CI; e2e GitHub secrets and the absent-secret skip/fail rules are removed | CI runs the same harness on the runner, so e2e always runs where required |
| 2026-10-22 | Remove the e2e sweeper workflow and cloud test organization references | Each e2e run uses a fresh kind cluster, so nothing leaks between runs |
| 2026-10-22 | `ProxyRecord` stays in e2e, asserting `Ready`, `Synced`, and deletion but not status `valid` | The provider does not wait for provisioning status, and `valid` is unreachable on self-host |
| 2026-10-22 | The `Subscription` example targets an insight via email, not an AI prompt | AI prompts are cloud-only |
| 2026-10-22 | Module path `github.com/Cliftonz/provider-upjet-posthog`, provider name `posthog`, root group `posthog.m.clifton.quest`, package `provider-posthog`, image and xpkg orgs `xpkg.upbound.io/cliftonz` | Section 1 identity and Upbound organization |
| 2026-10-22 | `go.mod` requires `github.com/posthog/terraform-provider v1.0.25` replaced by `Cliftonz/terraform-provider-posthog@e708a31` (resolved to a pseudo-version) until fork tags exist; upjet `v2.5.1`; MVS lifts terraform-plugin-sdk/v2 to v2.40.0, which builds with plugin-go v0.31.0 | Section 2 pins; the fork tag `v1.0.25-public` is a later human step (superseded by: 2026-10-24 fork pin `e6958dd`) |
