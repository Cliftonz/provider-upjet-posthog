# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-10-22 | Port the official PostHog hobby stack into kind; running compose beside kind is the fallback | The human asked for PostHog in kind |
| 2026-10-22 | Bootstrap an enterprise License row for local dev/test | `ee/LICENSE` permits dev/test use |
| 2026-10-22 | Adopt the e2e expectation matrix from research; `warehouse_table` is unknown pending the harness | Self-hosted behavior per resource was researched; `warehouse_table` cannot be confirmed until the harness runs |
| 2026-10-22 | e2e credentials (API key, organization ID, project ID, second user UUID) come from the harness bootstrap locally and in CI; e2e GitHub secrets and the absent-secret skip/fail rules are removed | CI runs the same harness on the runner, so e2e always runs where required |
| 2026-10-22 | Remove the e2e sweeper workflow and cloud test organization references | Each e2e run uses a fresh kind cluster, so nothing leaks between runs |
| 2026-10-22 | `ProxyRecord` stays in e2e, asserting `Ready`, `Synced`, and deletion but not status `valid` | The provider does not wait for provisioning status, and `valid` is unreachable on self-host |
| 2026-10-22 | The `Subscription` example targets an insight via email, not an AI prompt | AI prompts are cloud-only |
| 2026-10-22 | Module path `github.com/Cliftonz/provider-upjet-posthog`, provider name `posthog`, root group `posthog.m.clifton.quest`, package `provider-posthog`, image and xpkg orgs `xpkg.upbound.io/cliftonz` | Section 1 identity and Upbound organization |
| 2026-10-22 | `go.mod` requires `github.com/posthog/terraform-provider v1.0.25` replaced by `Cliftonz/terraform-provider-posthog@e708a31` (resolved to a pseudo-version) until fork tags exist; upjet `v2.5.1`; MVS lifts terraform-plugin-sdk/v2 to v2.40.0, which builds with plugin-go v0.31.0 | Section 2 pins; the fork tag `v1.0.25-public` is a later human step |
| 2026-10-22 | `config/provider.go` uses `WithIncludeList(nil)`, a framework include list of all 26 resources, and `WithTerraformPluginFrameworkProvider(provider.New(version)())` | No-fork mode; a resource on both paths panics at startup |
| 2026-10-22 | `cmd/generator` runs a single namespaced `PipelineRunner`; the storage-version and lifecycle post-generation hooks are dropped | `pipeline.Run` cannot generate namespaced-only, and there is a single version `v1alpha1` |
| 2026-10-22 | `cmd/provider` is namespaced only, sets an `OperationTrackerStore`, and has no Terraform flags | No Terraform CLI path at runtime |
| 2026-10-22 | Cluster-scoped trees and the legacy cluster `ProviderConfig` are removed; `ProviderConfig`, `ClusterProviderConfig`, `ProviderConfigUsage` stay in `posthog.m.clifton.quest/v1beta1` | Section 1 scope |
| 2026-10-22 | Every resource has an explicit short group and kind per section 4.2; managed resource version is upjet's default `v1alpha1` | Section 4 |
| 2026-10-22 | External names use `FrameworkResourceWithComputedIdentifier("id", placeholder)`: `0` for Int64 IDs and the project-ID singletons, the zero UUID for UUID IDs, `0/placeholder` for `project_member` and `access_control` | Upstream reads singletons, `dashboard_layout`, `project_member`, `access_control` and `organization_member` from parameters, so the placeholder only has to be non-empty and never match a real ID; the external name becomes the upstream state ID after the first read |
| 2026-10-22 | References: `project_id` on every project-scoped kind, plus role, organization member, insight, dashboard, feature flag and logs alert ID fields; `organization_id`, `user_uuid`, experiment `holdout_id`, access control `resource_id`, subscription `integration_id` get none | No kind owns those IDs, or the target kind varies |
| 2026-10-22 | Cross-group import cycles in resolvers are broken with upjet's resolver transform and `internal/apis.GetManagedResource` | `analytics` and `dashboard`, `project` and `access` reference each other |
| 2026-10-22 | Credentials Secret JSON keys `api_key`, `host`, `organization_id`, `project_id` are passed through only when non-empty; an empty `api_key` counts as missing | An empty string must never reach upstream, which treats a set value as authoritative |
| 2026-10-22 | `config/schema.json` is built from the fork binary via terraform 1.5.7 `dev_overrides`, without `init`; `pull-docs` fetches the fork at `TERRAFORM_PROVIDER_REF` | Section 2 schema source; `dev_overrides` worked so no filesystem mirror is needed |
| 2026-10-22 | Runtime image contains only the provider binary | Section 2 |
| 2026-10-22 | golangci-lint raised to 2.14.0 and `goconst` excluded under `config/` | 2.13.0 cannot read Go 1.27 export data; the resource tables repeat group and resource names by design |
| 2026-10-22 | `secretRef.namespace` stays required on `ProviderConfig`; the provider overrides it with the managed resource's namespace | The CRD requires the field; dropping it would diverge from the shared credentials schema |
| 2026-10-22 | An empty `api_key` is treated as missing | An empty string must never reach upstream |
| 2026-10-22 | Non-string credential values are rejected as malformed JSON | Every credential key is a string in the upstream provider configuration |
| 2026-10-23 | Tracking logic lives in `cmd/tracking` (Go, in the main module) and small `hack/*.sh` scripts; the new-resource gate reads the configured resource list from `config.GetProvider()` | One source of truth for section 4.2; the logic with branches gets unit tests |
| 2026-10-23 | `hack/upstream-acks.yaml` is keyed by upstream version without `v`, with `skip: true`, `breaking` (gate IDs) and `new_resources` (Terraform names); matching is exact string equality | The gates print the IDs a human copies into the file |
| 2026-10-23 | Breaking change IDs: `posthog_x` and `posthog_x.field[.field]` for `config/schema.json`; `<crd>`, `<crd>/<version>` and `<crd>/<version>:<path>` (`[]` for array items) for `package/crds`. A change is a removal or a changed type (Terraform type or nesting mode, OpenAPI `type`, array item type); added fields, including required ones, pass | Section 9 names removed resources, removed fields, and changed field types only |
| 2026-10-23 | The CI CRD check compares against the GitHub release marked latest and reads acknowledgements for the version in the Makefile's `TERRAFORM_PROVIDER_VERSION` | CI has no other version; on `upstream/v*` PRs this is the tracked version |
| 2026-10-23 | "Our latest release" is the highest semver among our GitHub releases; with no release, tracking finds nothing pending | A version tagged but not published must still count as unreleased; the first release is manual (section 10) |
| 2026-10-23 | Upstream prereleases are releases flagged `prerelease` or carrying a semver prerelease suffix; drafts are ignored | Section 9 |
| 2026-10-23 | Failure labels: rebase or post-rebase fork checks `fork-rebase`; checks on an existing fork tag `fork-fix`; pin bump `build`; PR state, PR opening, tag dispatch, closed unmerged PR, and `tag.yaml` `release`; `publish-provider-package.yml` `publish`; on `upstream/v*` PRs, CI `check-diff` `generation`, lint and build `build`, CRD check `breaking-change`, unit tests and example validation `test`, e2e `test` | Section 9 leaves these steps unassigned |
| 2026-10-23 | Detection failures (no version known) and failures on PRs not from `upstream/v*` open no issue; the run stays red | The issue title requires a version, and the next daily run retries detection |
| 2026-10-23 | Tracking always builds from `main`, force-pushes `upstream/v<version>`, and enables squash auto-merge; the tag goes on the squash commit | Fixes for a failed run land on `main` (section 13) |
| 2026-10-23 | `tag.yaml` dispatches `publish-provider-package.yml` after tagging (tags are lightweight, created through the API); tag and publish share concurrency group `release`; tracking uses `upstream-tracking`; e2e uses `e2e-<ref>` with cancel-in-progress | Dispatch carries the version, which `workflow_run` does not |
| 2026-10-23 | The OCI tag is `v<version>` (`xpkg.upbound.io/cliftonz/provider-posthog:v1.0.25`); workflow `version` inputs omit the `v` | Section 10 says the git tag and OCI tag are the same string; section 8's `:<version>` is read as that string |
| 2026-10-23 | GitHub App credentials are repository secrets `APP_CLIENT_ID` and `APP_PRIVATE_KEY`; the tracking token covers this repository and the fork | Section 12 |
| 2026-10-23 | e2e contract: after checkout with submodules and Go setup, `e2e.yaml` runs `test/harness/up.sh` then `hack/e2e.sh` (no arguments, repo root); `hack/e2e.sh` builds the package, installs Crossplane and the provider, and runs the tests. A `labeled` event runs e2e only for the `run-e2e` label | Section 11; the harness and runner belong to the e2e lane |
| 2026-10-23 | CI jobs and required check names: `lint`, `check-diff`, `unit-tests`, `build`, `example-validation`, `crd-breaking-changes`, plus `e2e` on `upstream/v*` and `upjet/*` PRs; the template's no-op detection, codecov, local-deploy and crddiff jobs are dropped | Section 8 |
| 2026-10-23 | Fork rebase moves new files under `internal/provider` to `provider/` without rewriting imports; the Go directive is raised only when upstream's is higher; the Makefile's `TERRAFORM_PROVIDER_REF` becomes the fork tag | Section 9 step 1 and 2 |
| 2026-10-23 | Breaking changes also include an added required field and an optional field made required (`config/schema.json` attribute `required`), a newly required CRD property (`required` lists), a new `x-kubernetes-validations` rule (compared by rule text; ID is the path of the schema holding it), and a removed or retyped map value schema (`additionalProperties`; ID segment `{}`). Reverses "added fields, including required ones, pass" | Human ruling: these reject manifests that were valid against the previous release |
| 2026-10-23 | No job holding the GitHub App token runs upstream code. Upstream tracking runs as `detect` (App token; our code only), `fork` (unprivileged: rebase and fork checks, git bundle artifact), `fork-push` (App token: push branch and tag with a lease on the pre-rebase SHA), `generate` (unprivileged: bump, generate, build, gates, patch artifact), `pr` (App token: commit the patch through the index, push, open the PR, enable auto-merge) and `report`. Publish builds and pushes the package in a job without the App token. CI, e2e and publish open failure issues from separate jobs that check out the default branch | Human ruling on token isolation; the fork tag must be published before `make generate` can resolve it, so the fork push sits between the two unprivileged jobs |
| 2026-10-23 | Every checkout sets `persist-credentials: false`; pushes use an explicit `x-access-token` URL in the step that holds the token; the unprivileged jobs get the git identity from `detect` outputs | Human ruling on token isolation |
| 2026-10-23 | Fork checks run the fork's full `go test ./...` plus the external-import check; acceptance tests stay skipped without `TF_ACC` | Human ruling |
| 2026-10-23 | `open-pr.sh` fails the step when enabling auto-merge fails, which opens a `release` issue through the existing failure path | Human ruling |
| 2026-10-23 | Upstream tags that are not valid semver are not releases and are ignored; our draft and prerelease GitHub releases do not count as our latest release | Human ruling |
| 2026-10-23 | Publish treats only "not found" as absent for the OCI tag check (`imagetools inspect` output containing `not found`) and `gh release view` (`release not found`); any other error fails the job | Human ruling |
| 2026-10-23 | `ci.yml` runs on `push` to `main` and on `pull_request` | Human ruling: no double runs on PR branches |
| 2026-10-23 | `hack/labels.sh` creates the 11 issue labels (`upstream-tracking`, `fork-rebase`, `fork-fix`, `generation`, `build`, `test`, `breaking-change`, `new-resource`, `publish`, `release`, `skip`) with `gh label create --force`; run once during section 12 setup | Human ruling |
| 2026-10-23 | The tracking cron `17 6 * * *` stays; release notes come from `--generate-notes`; publish marks the GitHub release latest with `--latest` | Human ruling |
| 2026-10-23 | The tracking `pr` job accepts the generate patch only if every path (both sides of a rename) is under `apis/`, `internal/controller/`, `package/crds/`, `examples-generated/` or is `config/schema.json`, `config/provider-metadata.yaml`, `go.mod`, `go.sum`, or `Makefile` with only `TERRAFORM_PROVIDER_VERSION` and `TERRAFORM_PROVIDER_REF` lines changed; otherwise it fails with a `generation` issue listing the paths. Checked by `tracking patch-paths` | Human ruling: generation runs upstream code and the PR auto-merges, so it must not change scripts or tooling later run with the App token |
