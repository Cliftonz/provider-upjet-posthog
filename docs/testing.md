# Testing

Every check is one command that exits non-zero on failure. Commands run from the repository root under bash (WSL or Linux) with Docker, kind, kubectl, jq, curl and Go on `PATH`; the harness checks also need envsubst and openssl ([test/harness/README.md](../test/harness/README.md)).

| Check | What it proves | Command | Runs automatically | Duration |
|---|---|---|---|---|
| Lint | golangci-lint passes on the Go code | `make lint` | `ci.yml` job `lint` on push to `main` and every PR | about 5 min |
| Repository checks | every tracked `*.sh` is mode `100755`; `cmd/tracking`, which runs with the GitHub App token, links no upstream provider package; the Makefile `TERRAFORM_PROVIDER_REF` matches the `go.mod` fork pin | `make repo-checks` | `ci.yml` job `lint` | under 1 min |
| Generation diff | `make generate` reproduces the committed generated code, CRDs and examples | `make check-diff` | `ci.yml` job `check-diff` | about 10 min |
| Go unit tests | credential mapping, provider config resolution, external names, ID and JSON conversions, and the tracking tool (fork tag, pending version, skips, schema and CRD diff, gates, patch paths) | `make test` | `ci.yml` job `unit-tests` | about 3 min |
| Script tests | shellcheck passes on every tracked script; bats tests of the scripts with branches: tag, push, failure issue, bump, fork rebase, breaking-change skip, fresh harness, Upbound diagnostics, repository checks, the simulation's version selection, `VERSION` required by `make e2e-release` and `make install-check` | `make test-scripts` | `ci.yml` job `script-tests` | under 1 min |
| Build | the provider image and `.xpkg` build for `linux_amd64` and `linux_arm64` | `make -j2 build.all` | `ci.yml` job `build` | about 15 min |
| Example validation | every manifest under `examples/namespaced` passes a server-side dry-run against `package/crds` in a throwaway kind cluster | `make example-validation` | `ci.yml` job `example-validation` | about 3 min |
| CRD breaking changes | no CRD removal, retype or new requirement against the latest GitHub release, except those acknowledged in `hack/upstream-acks.yaml` | `GH_TOKEN=... hack/breaking-changes.sh crds` | `ci.yml` job `crd-breaking-changes` | about 1 min |
| End to end, local build | every example except `Table` creates, updates, imports and deletes against self-hosted PostHog, with API assertions from the hooks, including the lock flag toggle (`featureflag-lock.yaml` runs `testhooks/lock-toggle.sh`) and a `ClusterProviderConfig` reading a Secret in another namespace | `test/harness/up.sh && make e2e-local` | `e2e.yaml` on `upstream/v*` and `upjet/*` PRs, PRs labeled `run-e2e`, and `workflow_dispatch` (one lane) | 45 min first boot from a snapshot, then about 12 min per run with three lanes |
| One example | one example file passes uptest on the running harness `E2E_CLUSTER` | `make e2e-example EXAMPLE=examples/namespaced/<group>/v1alpha1/<file>.yaml` | local only | 1 to 5 min |
| Released package | install check (below), then end to end with the published Upbound package, on a fresh harness cluster `posthog-release` (port 30802) that is deleted afterwards | `make e2e-release VERSION=vX.Y.Z` | `release-check.yml`, called by `publish-provider-package.yml` after the Upbound push and the GitHub release succeed, and `workflow_dispatch` with a version | about 70 min |
| Install check | both registry refs (`xpkg.upbound.io` and `ghcr.io`) pull without credentials; each installs into a throwaway kind cluster, becomes Healthy, and a FeatureFlag through a ProviderConfig becomes Ready, is visible through the PostHog API and is soft-deleted when its managed resource is deleted | `make install-check VERSION=vX.Y.Z` (needs the running harness `E2E_CLUSTER`) | inside `make e2e-release` | about 10 min |
| Harness snapshot | with no snapshot for the current harness inputs, a fresh cluster bakes one; a second fresh cluster restores it and PostHog's startup migrate applies no Django migration | `make harness-snapshot-check` (cluster `posthog-snapshot`, port 30803) | local only; `e2e.yaml` job `snapshot` bakes the CI snapshot on push to `main` | about 20 min, 70 min when it bakes |
| Upstream tracking simulation | the tracking pipeline (detect, skips, fork tag, fork checks on an existing tag, fork rebase onto the upstream tag, bump, generate, build, unit tests, both gates, patch paths) and the publish build pass on scratch clones that cannot push, with a gh stub; a patch touching `hack/` is rejected; an injected removed field fails the breaking-change gate and passes once acknowledged; a fake new resource fails the new-resource gate and passes once acknowledged; a skip entry skips the version | `make simulate-tracking` (`SIM_VERSION`, `SIM_LATEST`, required when `SIM_VERSION` is not a stable release with a predecessor; `SIM_E2E=1` adds end to end on a fresh harness `posthog-sim`) | `simulate-tracking.yml` weekly (Monday 04:41 UTC) and `workflow_dispatch`, without end to end | about 60 min, plus about 60 min with `SIM_E2E=1` |
| Fork checks | the fork's `go test ./...` and the external-import check | `hack/fork-checks.sh FORK_DIR` | `upstream-tracking.yml` job `fork`; inside `make simulate-tracking` | about 5 min |
| Upbound credentials | lengths, shapes and whitespace of `XPKG_ACCESS_ID` and `XPKG_TOKEN`, and whether `docker login` and `up login` accept them, without printing either | `XPKG_ACCESS_ID=... XPKG_TOKEN=... hack/diagnose-upbound.sh` | `publish-provider-package.yml` job `upbound`, when a step fails | under 1 min |

## Not automated

- Filing upstream issues and PRs stays with the human (SPEC.md section 14).
- Choosing whether to acknowledge a breaking change or a new resource, or to skip a version, is a human ruling recorded in `hack/upstream-acks.yaml`; the gates and the simulation only prove the rulings take effect.
- The weekly simulation runs without end to end on GitHub: a hosted runner fits the PostHog harness and one lane, but not the harness next to the tracking build within the job's time.
